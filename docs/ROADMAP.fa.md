# رودمپ پایدارسازی و بازیابی WireDash — فارسی

مبنای شروع `main`: کامیت `58fa826862c7a17bdc6a832e1122d14de282e464`؛ شاخهٔ کار: `work/stability-backup-roadmap-20260921`. توسعه در شاخه و کانتینر تست؛ هرگونه نصب، بازسازی کانتینر یا ری‌استارت VPN اصلی نیازمند تأیید مجدد است.

## شواهد فعلی و محدودیت‌ها

- سه دیتابیس اصلی در حالت WAL گزارش شدند؛ Gunicorn اصلی دستی روی یک Worker و یک Thread تنظیم شد؛ پس از Reload پاسخ HTTP موفق و `wg0` فعال بود. **حل دائمی هنگ پنل هنوز ثابت نشده است.** تنظیم دستی داخل کانتینر ممکن است با بازسازی از بین برود.
- تست مستقل با Volumeهای جدا اما VPS مشترک: ۵۰۰ ساخت و ۵۰۰ حذف در پنج دستهٔ ۱۰۰تایی و چهار درخواست کلاینت هم‌زمان با WAL و یک Thread پاس شد. این تست ۵۰۰ کاربر فعال هم‌زمان نیست.
- در تست دو Thread خطای `wg-quick save`، IP نامعتبر `'N'` و قالب‌بندی اشتباه لاگ دیده شد؛ علت نهایی نیازمند بررسی کد است. ربات‌های فروش قابل تغییر نیستند و حل هم‌زمانی باید سمت پنل انجام شود.
- ZIP ارسالی حاوی **اسکریپت** `wgdashbackup-v3.sh` است، نه بکاپ واقعی اطلاعات سرور. فایل‌های واقعی کاربران، دیتابیس، کلیدها، `.env` و توکن‌ها نباید به مخزن عمومی GitHub بروند.

## CP0 — تثبیت مبنا

ثبت SHA و ریسک‌ها، شاخهٔ مستقل، کامیت‌های کوچک و Pull Request؛ تست/برگشت هر تغییر و بدون دستکاری Production در زمان توسعه.

## CP1 — بکاپ امن و بازگشت

ممیزی اسکریپت v3، بررسی ورودی و آرشیو، ignore فایل‌های محرمانه، بکاپ آنلاین SQLite، `quick_check`، هش SHA-256 و آزمون بازیابی روی تست. رمزنگاری قبل از ارسال به محل ذخیرهٔ بیرونی و حفاظت root-only از توکن تلگرام. تنها اسکریپت بدون رمز در GitHub قرار می‌گیرد. بعد از نصب و آزمون، دستور README: `sudo wgdashbackup --backup`؛ دستور Restore جداست و ممکن است VPN را متوقف کند.

## CP2 — WAL، هم‌زمانی و رفع هنگ (اولویت اصلی)

WAL دائمی برای هر دیتابیس؛ busy_timeout برای **تک‌تک اتصال‌ها** و تنظیم دوام و checkpoint پس از بررسی. قفل درست بین Thread/Process برای تمام زنجیرهٔ ساخت/حذف/ویرایش Peer، تخصیص IP، DB، رابط فعال، ذخیرهٔ کانفیگ و پاسخ؛ نه جایگزینی خطرناک باینری `wg-quick`. جلوگیری از IP تکراری و حل وضعیت «ساخته شده ولی پاسخ خطا». ثبت خطای پاک‌سازی‌شده و معیار زمان پاسخ. تنظیم Gunicorn پایدار در Docker با مقدار پایهٔ آزموده‌شدهٔ یک Thread تا اصلاح درست قفل‌ها. قبولی: ۵۰۰ ساخت/حذف با چهار کلاینت، بدون خطا و Peer اضافه در API/DB/config/runtime، همراه با تزریق خطا.

## CP3 — پورت انتخابی و مسیریابی

تنظیم هماهنگ UDP port، ListenPort، endpoint، Docker mapping و firewall برای WireGuard و AmneziaWG؛ بررسی تداخل پورت، forwarding، NAT، مسیر برگشت، DNS، MTU، AllowedIPs و IPv4/IPv6؛ تست ارسال/دریافت واقعی، نه صرف handshake. تغییر فایروال اصلی یا بازسازی کانتینر فقط پس از تست و تأیید جداگانه.

## CP4 — Watchdog و تلگرام

بررسی جداگانهٔ وب، API و VPN با چند تلاش، هشدار خطای پالایش‌شده و رفع حادثه در تلگرام با محدودیت تعداد پیام. بازیابی کنترل‌شدهٔ فقط وب، محدودیت retry و cooldown؛ **بدون ری‌استارت خودکار کل VPN/کانتینر بدون تأیید و آزمون**. بکاپ‌گیر مستقل بماند.

## CP5 — نصب یک‌دستوری و انتشار

ایمیج نسخه‌دار، Compose با Volume دائمی، نصب‌کنندهٔ قابل تکرار، تست نصب/ارتقا/Restore، README و rollback با Tag/SHA. دستور هدف: `git clone https://github.com/smorad3363/WireDash.git && cd WireDash && sudo bash scripts/install.sh`؛ **هنوز install.sh ساخته نشده؛ دستور فعلاً اجرا نشود.** پس از نصب معتبر دستور بکاپ `sudo wgdashbackup --backup` منتشر می‌شود. پاک‌کردن `wgd-loadtest` و Volumeهای مخصوصش صرفاً بعد از کنترل پاک‌سازی و حفظ لاگ‌ها.

ترتیب کار CP0 تا CP5 است. هر مرحله کامیت، تست، rollback و وضعیت PR جدا دارد؛ شکست تست مانع استقرار روی پنل اصلی است. کلید API تست که در چت منتشر شده باید باطل شود.
